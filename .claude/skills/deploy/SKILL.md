# Выкладка журнала на прод

Порядок ниже выведен ошибками, а не теорией. Каждый шаг существует потому,
что без него проект уже ломался. Пропускать шаги дороже, чем выполнить.

## 1. Проверить типы и собрать

```bash
npm run typecheck
rm -rf .next && npm run build
```

Собирать **без** `| head`, `| tail` и прочих труб. Труба закрывается раньше,
чем `next build` дописывает `prerender-manifest.json`, процесс получает SIGPIPE
и умирает посреди записи. Файл остаётся нулевой длины, сборка формально
«прошла», а `next start` падает с `Unexpected end of JSON input`. Если вывод
нужно сократить — пиши его в файл и потом читай файл:

```bash
npm run build > /tmp/build.log 2>&1; echo "exit: $?"
grep -E "✓ Compiled|✓ Generating|Error" /tmp/build.log | head -5
```

`rm -rf .next` перед сборкой нужен, чтобы мусор прошлой сборки не выдавал
сломанное состояние за рабочее.

## 2. Закоммитить и запушить

Ветка разработки — `claude/school-electronic-journal-2zkbdj`.

```bash
git add -A
git commit -F - <<'EOF'
Заголовок по-русски, до 72 символов

Что изменилось и ПОЧЕМУ. Причина важнее списка файлов: дифф и так виден,
а вот почему принято именно такое решение — нет.
EOF
git push gh claude/school-electronic-journal-2zkbdj
```

Пушить в remote **`gh`**, а не в `origin`. `origin` смотрит на локальный
git-прокси песочницы и отдаёт `403` на запись. Проверить, куда что смотрит:
`git remote -v`.

Пул-реквест не создавать, если о нём не попросили явно.

## 3. Задеплоить

```bash
vercel deploy --prod --yes --token "$VERCEL_TOKEN"
```

Токен в репозитории не хранится и в скилл не вписан — его даёт пользователь
или он лежит в окружении. Если токена нет, попроси его, но предупреди, что
токен, отправленный в переписку, считается скомпрометированным и его нужно
будет отозвать.

Проект уже связан (`.vercel/project.json`), поэтому вопросов про связывание
деплой не задаст. Сборку на Vercel выполняет скрипт `vercel-build`:
`prisma generate && prisma migrate deploy && tsx prisma/bootstrap.ts && next build`.
Значит миграции применяются автоматически, а `bootstrap.ts` идемпотентен —
администратора он создаёт, только если ни одного администратора нет.

## 4. Убедиться, что миграции легли

Деплой со статусом READY ещё не значит, что база в порядке — посмотри логи:

```bash
vercel inspect --logs <url-деплоя> --token "$VERCEL_TOKEN" 2>&1 | grep -iE "migration|applied"
```

Ждём строки `Applying migration ...` и `All migrations have been successfully applied.`
Если `migrate deploy` падает, сборка обрывается и деплой не становится READY —
но проверить дешевле, чем узнать об этом от учителя посреди урока.

## 5. Проверить живой прод

**Боевой адрес — `https://school-journal-six.vercel.app`.**

Три ловушки с адресами:
* `school-journal.vercel.app` — **чужое приложение** на Create React App.
  Домен глобальный, его занял кто-то другой. Никогда не давай эту ссылку.
* Адрес конкретного деплоя (`school-journal-<хеш>-swami654.vercel.app`)
  закрыт защитой Vercel и редиректит на `vercel.com/sso-api` — проверять
  на нём бесполезно.
* Список рабочих псевдонимов: `vercel inspect <url> --token "$VERCEL_TOKEN"`.

Проверка защиты — она важнее внешнего вида, потому что ученики умеют
открывать чужие ссылки:

```bash
c() { curl -s --noproxy '*' "$@"; }   # кавычки вокруг * обязательны:
                                      # без них шелл раскроет глоб в имена файлов
U=https://school-journal-six.vercel.app
c -o /dev/null -w "%{http_code}\n" -L "$U/login"                       # ждём 200
c -o /dev/null -w "%{http_code}\n" "$U/journal"                        # ждём 307 на /login
c -o /dev/null -w "%{http_code}\n" "$U/admin/audit"                    # ждём 307
c -o /dev/null -w "%{http_code}\n" "$U/api/journal/export?subject=x&quarter=1"  # ждём 401
```

`307` на страницах и `401` на маршруте экспорта — это и есть доказательство,
что серверная проверка ролей работает. `200` везде означает, что ты смотришь
не на то приложение (см. ловушки выше).

## Чего не делать

* Не ставить `RESET_DATA=true`, если пользователь не попросил стереть базу
  осознанно: переменная удаляет **все** данные при следующем деплое.
* Не коммитить `.env` — `.vercelignore` **заменяет** `.gitignore` при выгрузке
  на Vercel, поэтому секретные файлы перечислены в нём отдельно и явно.
* Не откатывать прод «на всякий случай»: у школы данные живые, откат схемы
  теряет оценки.
