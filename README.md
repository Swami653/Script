# Электронный журнал

Веб-приложение школьного электронного журнала: **10-балльная система оценок**,
**4 учебные четверти**, три роли — администратор, учитель, ученик.

## Возможности

**Администратор** — панель управления, статистика, создание учётных записей,
**массовый импорт учеников** (вставьте список ФИО текстом — логины и временные
пароли создадутся сами), сброс паролей, смена ролей.

**Учитель** — журнал класса (строки — ученики, столбцы — уроки), переключение
предметов, четвертей и учебных лет, выставление оценок кликом или с клавиатуры,
**две оценки за один урок** («10/9» за контрольную), **типы работ** (контрольная,
домашняя, устный ответ), **комментарий к оценке**, **отметка «Н»** и подсчёт
пропусков, управление предметами и уроками, **границы четвертей и учебный год**,
карточка ученика, экспорт в CSV.

**Ученик** — собственный дневник: таблица предметов со средними баллами за каждую
из четырёх четвертей и годовой оценкой, **график динамики**, **разбор по предмету**
(дата урока, тема, тип и комментарий оценки, пропуски), лента последних оценок.

## Стек

Next.js 15 (App Router) · TypeScript · Tailwind CSS · Prisma + PostgreSQL ·
NextAuth.js v5 (Credentials + bcrypt) · Zod · Lucide Icons

## Запуск

```bash
npm install
cp .env.example .env      # подставьте DATABASE_URL, DIRECT_URL и AUTH_SECRET
npm run setup             # prisma generate + миграции + аккаунт администратора
npm run dev               # http://localhost:3000
```

Нужна доступная база PostgreSQL: локальная, в Docker или отдельная ветка Neon.

`npm run setup` применяет миграции и создаёт **одного администратора** из переменных
`ADMIN_USERNAME` и `ADMIN_PASSWORD`. Демонстрационных учеников и оценок нет —
журнал наполняется реальными данными через панель администратора.

Вход выполняется **по логину**, а не по почте. Логины учеников при массовом импорте
создаются транслитерацией ФИО: «Иванов Иван Иванович» → `ivanov.i.i`.

## Как считаются оценки

- Оценка — целое число от 1 до 10.
- За один урок можно поставить **две оценки** («10/9» за контрольную) — это две
  отдельные целые оценки, каждая идёт в средний балл самостоятельно.
- Средний балл за четверть — среднее арифметическое всех оценок,
  округление до сотых (`7.45`). Отметка «Н» в средний балл не входит.
- Годовая оценка — среднее средних баллов непустых четвертей, округление до целого
  1–10 (`0.5` вверх).

## Горячие клавиши в журнале

| Клавиши | Действие |
|---|---|
| `←` `→` `↑` `↓` | перемещение по ячейкам |
| `1`…`9` | выставить оценку |
| `0` или `10` | выставить 10 |
| `Enter` | открыть выбор оценки мышью |
| `Shift` + цифра | вторая оценка за тот же урок |
| `Delete` / `Backspace` | убрать последнюю оценку клетки |
| `Shift` + `Delete` | очистить клетку целиком |

После выставления оценки фокус переходит к следующему ученику — столбец
заполняется без мыши.

## Безопасность

- Пароли хранятся только как bcrypt-хеши. Временный пароль, выданный администратором,
  виден в панели до первого входа пользователя, после чего стирается — «подсмотреть»
  используемый пароль невозможно ни администратору, ни разработчику.
- Роль проверяется на сервере в каждом Server Action и Route Handler
  (`requireRole` в `src/lib/auth-guards.ts`): ученик получает 403 и не может
  изменить ни одной оценки, даже отправив запрос в обход интерфейса.
- Оценка валидируется схемой Zod: только целое число 1–10.
- Middleware — дополнительный, а не единственный рубеж защиты.

Подробные правила проекта — в [CLAUDE.md](./CLAUDE.md).

## Развёртывание

Приложение работает на PostgreSQL (проверено на Neon + Vercel).

1. Подключите базу — например, интеграцию **Neon** в панели Vercel.
2. Задайте переменные окружения проекта:

   | Переменная | Значение |
   |---|---|
   | `DATABASE_URL` | пулированная строка (`...-pooler...`) **с** `pgbouncer=true&connection_limit=1` |
   | `DIRECT_URL` | прямая строка без pgbouncer — для миграций |
   | `AUTH_SECRET` | `openssl rand -base64 32` |
   | `AUTH_TRUST_HOST` | `true` |
   | `ADMIN_USERNAME` / `ADMIN_PASSWORD` | учётка администратора для первого запуска |
   | `RESET_DATA` | `true` — **полная очистка базы** на один деплой, потом переменную убрать |

3. Разверните: `vercel deploy --prod`.

Сборка на Vercel идёт по скрипту `vercel-build`:

```
prisma generate && prisma migrate deploy && tsx prisma/bootstrap.ts && next build
```

Миграции применяются автоматически. `bootstrap.ts` идемпотентен: администратора он
создаёт, только если ни одного администратора в базе нет, поэтому повторные деплои
не трогают накопленные данные.

Почему две строки подключения: serverless-функции живут коротко и плодят
соединения, поэтому приложение ходит через пул (pgbouncer), а миграциям нужен
прямой канал — pgbouncer не поддерживает часть команд DDL-сессии.

**Не кладите `.env` в загрузку.** Файл `.vercelignore` заменяет `.gitignore`
при выгрузке на Vercel, поэтому локальные секреты перечислены в нём явно.

## Команды

```bash
npm run dev        # разработка
npm run build      # прод-сборка
npm run start      # запуск собранного приложения

npm run db:seed    # bootstrap: администратор (и очистка при RESET_DATA=true)
```
